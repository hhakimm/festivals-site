# 관광 통계 기반 "여행 결정 돕기" — 설계 (방안 A)

작성일: 2026-05-31
상태: 승인됨 (사용자 "ㄱㄱ")

## 목적
data.go.kr 관광 통계(지역×월 방문 데이터)를 활용해 사용자가 **어디로(WHERE) + 언제(WHEN)**
여행할지 결정하도록 돕는다. 사이트 목표(여행 결정 돕기 > 바이럴/SEO 부차)에 맞춘 가벼운 통합.

## 데이터
- **출처:** 주요관광지점 입장객통계(지역×월 입장객) — 한국관광 데이터랩 / 관광지식정보시스템.
- **취득 방식:** 깔끔한 빌드용 OpenAPI가 없으므로 **파일(CSV/Excel)을 1회 받아 저장소에 커밋**,
  빌드 때 파싱. 새 API 키·호출 한도·실패 위험 없음. 갱신은 연 1~2회 파일 교체.
- **정규화 산출물:** `src/content/stats/region-stats.json`
  ```
  {
    "<areacode>": {
      "monthly": number[12],   // 1~12월 상대 방문지수 (0~100, 그 지역 내 정규화)
      "share":   number,       // 전국 대비 그 지역 연간 방문 비중(%) — 인기 순위용
      "peak":    number[],     // 성수기 월 (지수 상위)
      "low":     number[]      // 비수기 월 (지수 하위)
    }, ...
  }
  ```
- 통계 지역명(시도) → 기존 `AREA_CODE` 키 매핑 (fetch-tourapi.ts의 매핑 재사용).
- 입장객 원자료(절대수)는 표시하지 않고 **상대 지수**로 가공(잠정치·방법론 차이 노출 최소화).

## 기능 (2개)
### (a) "📊 이번 달 인기 지역 TOP5" 위젯
- 위치: 홈 둘러보기(Explorer) 상단.
- 동작: `share`/현재 월 `monthly` 기준 상위 5개 지역을 칩으로. 클릭 시 해당 지역으로 필터.
- 현재 월은 **클라이언트 JS**가 판단 → 리빌드 없이 항상 정확. (데이터는 12개월 전체 임베드)
- 컴포넌트: `PopularRegions.astro` (+ 작은 client 스니펫).

### (b) 지역 페이지 "언제 가면 좋을까?"
- 위치: `/attractions/region/[area]/`, `/festivals/region/[area]/` (4개 언어) 상단.
- 내용: 월별 방문 추이 막대(12칸, 순수 CSS) + 성수기🔥/비수기💤 배지 + 한 줄 요약
  ("○○는 4·5·10월이 가장 좋아요").
- 컴포넌트: `RegionSeasonality.astro` (props: areacode, lang).

## 데이터 흐름
```
src/content/stats/region-stats.json   (커밋된 정규화 데이터)
        │  (필요 시 scripts/build-stats.ts 가 원본→정규화)
        ▼
src/lib/stats.ts   (areacode→지수 제공, 성수기/순위 계산 헬퍼)
        ▼
PopularRegions.astro (위젯) · RegionSeasonality.astro (추이)
```
- 정적 SSG 빌드 타임 계산. 출처 "통계: 한국관광공사" 표기.
- 차트는 라이브러리 없이 CSS bar. 검정+노랑 톤 유지.

## 안 하는 것 (YAGNI)
- 개별 장소 입장객 매칭(C안) — 이름 매칭 불안정.
- 외국인 입국 통계 — 국내 여행 결정과 무관.
- 별도 `/trends/` 페이지(B안) — 나중에 확장 여지로만.

## 위험 / 열린 항목
- **데이터 취득**: 정부 포털 자동 다운로드가 어려움 → 직접 받아 커밋하거나, 안 되면
  사용자에게 30초 다운로드 안내. 실제 파일을 보고 파서를 맞춘다(컬럼 추정 금지).
- 지역 단위가 시도(17개)면 충분. 시군구까지면 시도로 합산.
