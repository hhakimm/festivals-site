# 한국 축제 캘린더 사이트 — 설계 문서

**작성일:** 2026-05-02
**상태:** 1차 설계, 사용자 검토 대기

## 1. 목적

월별·지역별로 한국 국내 축제를 탐색할 수 있는 정적 웹사이트.
사용자는 두 가지 방식으로 축제를 찾는다:
- 시기 기준 — "5월에 갈만한 축제 뭐가 있지?"
- 지역 기준 — "경상남도 가는데 축제 뭐 있지?"
- 두 조건 동시 적용도 가능 ("5월 + 경상남도")

## 2. 범위

**포함:**
- 한국 국내 축제 60~80개 큐레이션 (정적 JSON)
- 월/지역/카테고리 필터
- 카드 그리드 + 상세 모달
- URL 쿼리 동기화 (공유 가능한 링크)
- 모바일 반응형

**제외 (YAGNI):**
- 사용자 계정/로그인
- 즐겨찾기/북마크 (URL 공유로 대체)
- 댓글, 평점
- 지도 통합 (1차 범위 외)
- 다국어 (한국어 전용)
- 관리자 페이지 (데이터 직접 편집)
- 외부 API 연동

## 3. 기술 스택

- **HTML + CSS + Vanilla JavaScript** (빌드 도구 없음)
- 데이터: `data/festivals.json` (정적 파일)
- 단위 테스트: 가벼운 테스트 러너 (예: `node --test` 또는 Vitest)
- 배포: 정적 호스팅 (GitHub Pages 등) — 본 문서 범위 외

**선택 이유:** 데이터가 자주 바뀌지 않고, 사용자 상호작용이 클라이언트 필터링에 한정됨. 빌드 단계와 프레임워크 의존성이 불필요.

## 4. 데이터 모델

`data/festivals.json` — 축제 객체 배열.

```json
{
  "id": "jinhae-gunhangje-2026",
  "name": "진해 군항제",
  "region": "경상남도",
  "city": "창원시 진해구",
  "startDate": "2026-03-25",
  "endDate": "2026-04-03",
  "category": "꽃",
  "description": "벚꽃이 만개한 진해에서 열리는 한국 대표 봄 축제.",
  "image": "images/jinhae.jpg",
  "officialUrl": "https://example.com/jinhae"
}
```

**필드 정의:**
| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | 예 | 고유 식별자 (slug 형식) |
| `name` | string | 예 | 축제명 |
| `region` | string | 예 | 시/도 (예: "경상남도", "서울특별시") |
| `city` | string | 예 | 시/군/구 (예: "창원시 진해구") |
| `startDate` | string (YYYY-MM-DD) | 예 | 시작일 |
| `endDate` | string (YYYY-MM-DD) | 예 | 종료일 (당일 행사면 startDate와 동일) |
| `category` | string | 예 | 카테고리 (아래 참조) |
| `description` | string | 예 | 한 줄~짧은 단락 설명 |
| `image` | string | 예 | 이미지 경로 또는 외부 URL |
| `officialUrl` | string | 아니오 | 공식사이트 (없으면 생략) |

**카테고리 (고정 셋):** `전통`, `음식`, `꽃`, `불꽃`, `음악`, `문화`, `겨울` (필요 시 확장)

**지역 (고정 셋, 17개 시/도):** 서울특별시, 부산광역시, 대구광역시, 인천광역시, 광주광역시, 대전광역시, 울산광역시, 세종특별자치시, 경기도, 강원특별자치도, 충청북도, 충청남도, 전북특별자치도, 전라남도, 경상북도, 경상남도, 제주특별자치도

## 5. 사용자 인터페이스

### 5.1 페이지 구조 (단일 페이지)

```
┌─────────────────────────────────────┐
│  헤더                                │
│   "한국 축제 캘린더"                  │
│   "월별·지역별로 떠나는 축제 여행"     │
├─────────────────────────────────────┤
│  필터 바 (스크롤 시 sticky)           │
│   월: [전체] [1] [2] ... [12]        │
│   지역: [드롭다운: 전체 / 17개 시도]   │
│   카테고리: [전체] [전통] [음식] ...   │
│   결과 개수: "총 24개의 축제"          │
├─────────────────────────────────────┤
│  카드 그리드                          │
│   3열 (≥1024px) / 2열 (≥640px) /    │
│   1열 (모바일)                        │
└─────────────────────────────────────┘
```

### 5.2 카드 디자인

각 카드:
- 16:9 대표 이미지 (상단)
- 축제명 (제목 폰트)
- 기간 (예: "3.25 — 4.3")
- 지역 (예: "경상남도 창원시")
- 카테고리 태그 (작고 둥근 배지, 카테고리별 색)
- 한 줄 설명 (말줄임 처리)
- 호버 시 살짝 들리는 효과 (transform/shadow)

### 5.3 상세 모달

카드 클릭 시:
- 큰 이미지
- 전체 설명
- 기간/지역/카테고리
- "공식사이트 가기" 버튼 (officialUrl 있을 때만)
- 닫기 버튼 + 모달 외부 클릭 시 닫힘 + ESC 키로 닫힘

### 5.4 빈 상태

필터 결과가 0개일 때:
- "선택한 조건에 맞는 축제가 없습니다."
- "필터 초기화" 버튼

### 5.5 디자인 톤

- 사진 중심 — 사진이 가장 두드러지게
- 배경: 오프화이트 (#FAFAF7)
- 텍스트: 다크그레이 (#222)
- 포인트: 따뜻한 코랄/오렌지 (#E8654C)
- 카테고리 태그 색상: 카테고리별 부드러운 톤 (꽃=핑크, 음식=옐로우, 불꽃=레드, 음악=퍼플 등)
- 폰트: 시스템 폰트 우선 (Pretendard fallback) — 외부 의존성 최소화

## 6. 동작 (필터 로직)

### 6.1 월 필터

축제의 `[startDate, endDate]` 기간이 선택한 월과 한 일자라도 겹치면 표시.
예: 12/30 — 1/3 축제는 12월, 1월 모두에서 표시됨.

```js
function isInMonth(festival, month) {
  const start = new Date(festival.startDate);
  const end = new Date(festival.endDate);
  // month: 1-12
  for (let d = new Date(start); d <= end; d.setDate(d.getDate() + 1)) {
    if (d.getMonth() + 1 === month) return true;
  }
  return false;
}
```

### 6.2 지역 필터

`region` 필드 정확히 일치.

### 6.3 카테고리 필터

`category` 필드 정확히 일치.

### 6.4 다중 필터

모든 활성 필터를 AND로 결합. "전체" 선택 시 해당 필터는 비활성.

### 6.5 정렬

기본: `startDate` 오름차순.
필터 적용 후에도 동일 정렬 유지.

## 7. URL 쿼리 동기화

필터 상태를 URL 쿼리 문자열에 반영해 공유/북마크 가능하게:

- `?month=5` — 5월
- `?region=경상남도` — 지역
- `?category=꽃` — 카테고리
- `?month=5&region=경상남도` — 조합
- `?festival=jinhae-gunhangje-2026` — 상세 모달 자동 열기

페이지 로드 시 쿼리 파싱 → 초기 필터 상태 설정.
필터 변경 시 `history.replaceState`로 URL 업데이트 (히스토리 오염 없음).

## 8. 파일 구조

```
festivals-site/
├── index.html              # 단일 진입점
├── css/
│   └── style.css           # 전체 스타일
├── js/
│   ├── app.js              # 메인 진입점 (이벤트 바인딩, 렌더링)
│   ├── filter.js           # 필터 로직 (순수 함수)
│   ├── url-sync.js         # URL 쿼리 ↔ 상태 동기화
│   └── modal.js            # 모달 열기/닫기
├── data/
│   └── festivals.json      # 축제 데이터
├── images/                 # 대표 이미지 (또는 외부 URL 사용)
├── tests/
│   ├── filter.test.js
│   └── url-sync.test.js
└── docs/
    └── superpowers/
        └── specs/
            └── 2026-05-02-korean-festivals-site-design.md
```

**모듈 경계:**
- `filter.js` — 순수 함수, DOM 의존 없음, 단위 테스트 가능
- `url-sync.js` — 순수 함수 (파싱/직렬화), 단위 테스트 가능
- `modal.js` — DOM 조작, 모달 한정
- `app.js` — 위 모듈들을 조합, 데이터 fetch, 렌더링

## 9. 테스트

**단위 테스트 대상:**
- `filter.js`: 월/지역/카테고리 단일/복합 필터, 경계 케이스 (월 걸치는 축제)
- `url-sync.js`: 쿼리 파싱, 상태 → 쿼리 직렬화, 빈 쿼리, 불완전 쿼리

**브라우저 수동 확인:**
- 필터 상호작용 시 카드 갱신
- 모달 열기/닫기 (클릭/ESC/외부 클릭)
- 반응형 (모바일/태블릿/데스크탑)
- URL 공유 동작

## 10. 에러 처리

- `festivals.json` fetch 실패 → "데이터를 불러오지 못했습니다. 새로고침해 주세요." 안내
- 이미지 로드 실패 → placeholder 이미지로 대체 (`onerror` 핸들러)
- 잘못된 URL 쿼리 → 무시하고 기본 상태로 진행

## 11. 데이터 시드 (초기 채우기)

1차 출시 기준 60~80개. 카테고리·지역 균형 있게.
예시 (실제 채울 때 검증 필요):
- 꽃: 진해 군항제, 구례 산수유꽃축제, 함평 나비축제, 고양 국제꽃박람회 …
- 음식: 보성 다향대축제, 강경 젓갈축제, 광양 매화축제 …
- 불꽃: 부산 세계불꽃축제, 포항 국제불빛축제 …
- 전통: 강릉 단오제, 안동 국제탈춤페스티벌 …
- 겨울: 화천 산천어축제, 태백산 눈축제 …
- 음악: 자라섬 재즈페스티벌, 인천 펜타포트 록페스티벌 …
- 문화: 진주 남강유등축제, 부산국제영화제 …

데이터 출처는 각 축제 공식사이트/관광공사 자료. 일자는 매년 변동되므로 1차는 2026년 기준으로 채우고, 이후 갱신 정책은 별도 결정.

## 12. 향후 확장 (현재 범위 외)

다음은 의식적으로 제외했지만 향후 가능한 방향:
- 검색창 (이름/설명 텍스트 검색)
- 즐겨찾기 (localStorage)
- 지도 뷰
- 다국어
- CMS/관리자 페이지
- 전 세계 축제 확장
- 캘린더 형식 뷰 (월별 그리드)

## 13. 성공 기준

- 사용자가 월/지역을 선택하면 즉시 결과가 갱신된다
- 모바일에서 한 손으로 스크롤·필터 조작이 자연스럽다
- URL을 복사해 공유하면 동일한 필터 상태가 재현된다
- 단위 테스트 모두 통과
- 첫 로드 시 1초 이내 카드 그리드 표시 (정적 파일이므로 자연스럽게 달성)
